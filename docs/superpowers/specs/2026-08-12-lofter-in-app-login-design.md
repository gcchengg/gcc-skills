# LOFTER Codex 内部浏览器登录设计

## 目标

`lofter-x-anime-hotspot` 的发布阶段固定使用 Codex 应用内浏览器。优先复用该浏览器已有的 LOFTER 登录状态；登录失效时由用户在页面中手动完成登录，之后从同一标签页继续当前运行。

## 浏览器选择

- 发布流程只使用 `browser:control-in-app-browser` 和应用内浏览器选择器 `agent.browsers.get("iab")`。
- 不因登录状态缺失自动切换 Chrome、Edge、外部浏览器或其他会话。
- 预览页可以继续显示在应用内浏览器；开始发布时新建或复用一个明确绑定当前运行的 LOFTER 编辑器标签。

## 登录暂停与恢复

1. 第一条精确确认“确认发布”通过后，生成并锁定 `upload-manifest.json`，再打开应用内浏览器中的 LOFTER 编辑器。
2. 若页面显示登录入口，Skill 停止填写并请求用户手动登录；不得读取或填写手机号、邮箱、密码、验证码。
3. 用户回复“已登录”后，重新取得应用内浏览器的现有标签，优先复用已经进入 LOFTER 的同一标签。
4. 只在页面明确显示已登录编辑器时继续；仍是登录页、出现 CAPTCHA、风控、账号验证或页面歧义时继续暂停。
5. 恢复过程不得重复执行第一确认、改变已批准上传清单或重新创建文章运行。

## 隐私与状态边界

- 不读取或保存密码、验证码、Cookie、localStorage、sessionStorage、请求头或浏览器配置。
- 本地状态只记录发布门禁、公开表单预览和文章结果，不记录登录凭证或会话标识。
- 浏览器标签 ID 仅作为当前执行期间的临时引用，不写入运行档案。

## 最终提交边界

登录恢复后仅按锁定清单填写标题、正文、标签和有序媒体。核对完成后停在最终提交按钮前；只有收到当前运行的精确短语“确认最终提交”，才允许点击一次。

## 验收标准

- Skill 文档明确规定发布阶段固定使用 Codex 应用内浏览器。
- 未登录场景给出“手动登录 → 回复已登录 → 同标签恢复”的确定流程。
- 测试或合同检查能防止发布说明重新允许自动切换 Chrome。
- 当前已批准但尚未填写的运行可以在用户登录后继续，无需重新生成图文。
