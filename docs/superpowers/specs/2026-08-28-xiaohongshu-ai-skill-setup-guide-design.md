# 小红书「AI Skill 装机指南」小工具设计

## 1. 产品概述

「AI Skill 装机指南」是一个挂载在小红书笔记下方的离线单页小工具。用户选择行业与岗位，再回答三个关于工作任务的问题，工具根据本地目录生成个性化 AI Skill 装机单。

产品不推荐具体 AI 软件，也不提供跨平台统一安装命令。真实开源项目以“可获取 Skill”呈现，附经过核验的 GitHub 链接；职业需要但缺少可信开源实现的能力，以“建议补充能力”单独呈现。

一句话定位：选择你的行业和岗位，三个问题生成一套适合你的 AI Skill 装机单。

## 2. 平台边界

设计遵循小红书小组件约束：

- 单个小组件只包含一个页面。
- 完整包体不超过 2MB。
- 使用纯 HTML、CSS 和 JavaScript。
- 不依赖 CDN，不发送网络请求。
- 所有行业、岗位、任务和 Skill 数据随包发布。
- 以笔记挂载和评论区提及作为主要分发入口。
- GitHub 状态不会在运行时刷新，页面必须显示目录版本及最近核验日期。

## 3. 用户与目标

### 3.1 目标用户

- 希望用 AI Agent 改善工作的职场人。
- 同时承担多个角色的复合职业者。
- 想了解本行业有哪些可用 Skill 的新人。
- 希望向团队或粉丝分享 AI 工作配置的创作者。

### 3.2 用户目标

- 快速了解本岗位需要哪些 AI Skill。
- 理解每个 Skill 能解决什么问题。
- 找到可信的开源仓库。
- 获得可保存、可分享的个人 Skill 装机卡。

### 3.3 非目标

- 不检测用户当前使用的 AI 软件。
- 不承诺 Skill 可在所有 Agent 平台安装。
- 不提供统一安装命令。
- 不在线搜索或实时更新 GitHub。
- 不把普通 Prompt 合集包装成可安装 Skill。

## 4. 产品流程

1. 炫酷入场动画。
2. 首页说明与开始按钮。
3. 选择行业。
4. 选择一至两个岗位。
5. 回答三道动态问题。
6. 播放短暂的 Skill 目录扫描动画。
7. 展示标准装机单。
8. 展开 Skill 详情或访问 GitHub。
9. 生成并保存分享卡。
10. 修改答案或重新测评。

完整流程目标时长不超过 60 秒。

## 5. 内容结构

### 5.1 行业

首版覆盖以下 20 个行业大类：

1. 软件与互联网
2. 产品与用户体验
3. 设计与创意
4. 自媒体与内容创作
5. 广告、市场与公关
6. 电商、直播与零售
7. 教育与培训
8. 金融、财会与保险
9. 法律、合规与咨询
10. 医疗、医药与生命科学
11. 制造、工业与工程
12. 建筑、地产与家居
13. 物流、采购与供应链
14. 餐饮、旅游与本地生活
15. 人力资源与企业行政
16. 科研、学术与出版
17. 政务、公益与公共服务
18. 农业、食品与乡村产业
19. 创业者与自由职业者
20. 学生、求职与职业转型

### 5.2 岗位与任务

- 首版包含 80 至 120 个岗位。
- 每个岗位关联带权重的任务标签。
- 总任务标签控制在 150 至 200 个。
- 用户最多选择两个岗位。
- 复合岗位合并任务权重，但单个标签设置上限，防止重复叠加垄断结果。

重点校验以下复合职业：

- 程序员 + 产品经理
- 设计师 + 自媒体
- 教师 + 内容创作者
- 电商运营 + 主播
- 创业者 + 市场负责人

### 5.3 三道动态问题

三道题分别识别：

1. 用户日常最常执行的工作任务。
2. 用户最希望 AI 改善的工作环节。
3. 用户最耗时或最容易出错的工作痛点。

题目选项根据已选岗位动态变化。每个答案只调整任务标签权重，不直接绑定固定 Skill，保证推荐逻辑可解释、可维护。

## 6. 推荐结果

标准装机单包含：

- 5 个必装 Skill。
- 5 个进阶 Skill。
- 3 个建议补充能力。
- 一个 AI 职业类型称号。
- 一句话职业画像。
- 五维能力雷达。

每个真实 Skill 卡片包含：

- Skill 名称。
- 一句话功能。
- 推荐级别。
- 为什么推荐给当前用户。
- 一个典型使用场景。
- GitHub 仓库链接。
- 最近核验日期。

真实 Skill 数量不足时不得重复或用低质量仓库凑数。缺口由明确标注的“建议补充能力”承接。

## 7. 推荐算法

推荐由四类信号构成：

- 岗位任务匹配：45%。
- 三题答案匹配：30%。
- 行业适配：15%。
- Skill 质量：10%。

推荐过程：

1. 读取行业基础任务权重。
2. 合并一个或两个岗位的任务权重。
3. 使用三道题答案调整权重。
4. 计算每个 Skill 与最终任务向量的匹配度。
5. 加入行业适配和质量分。
6. 对同类 Skill 去重并限制单一能力类别占比。
7. 选出必装与进阶结果。
8. 从未被真实 Skill 覆盖的高权重任务中生成能力建议。

页面展示具体推荐理由，不展示原始分数。

## 8. GitHub Skill 准入规则

每条仓库必须满足：

- 仓库在冻结数据当天可访问。
- README 能直接证明其功能。
- 仓库内容确实构成可复用 Skill，而非仅有营销文案。
- 用途、输入与输出基本明确。
- 不依据仓库名称或 Star 数单独判断质量。
- 不收录明显复制、失效、描述不清或含高风险行为的仓库。

质量分级：

- A 级：结构完整、文档清晰、维护状态良好，可进入必装。
- B 级：功能可信但维护或文档一般，可进入进阶。
- C 级：概念有价值但仓库质量不足，不展示仓库，转为能力建议。

每条记录保存名称、仓库、证据摘要、能力标签、行业、岗位、学习成本、质量等级、风险提示和核验日期。

## 9. 视觉与动画

整体风格采用深色赛博底、红色核心光、少量紫青极光及高对比白色内容。

首次进入的三秒动画依次为：

1. 极光与透视网格启动。
2. 多张 Skill 卡片从空间中聚合。
3. 多层轨道旋转并收束为核心 SK 图标。
4. 扫描光线经过。
5. 主标题从模糊状态显现。
6. 开始按钮落位并出现循环流光。

强动画只用于首次进入。同一会话返回首页时不强制重播，但提供重播入口。测评页、结果页和卡片展开只使用轻量过渡。所有动画支持 `prefers-reduced-motion`。

## 10. 页面设计

### 10.1 首页

- 品牌标识与本地运行说明。
- “干这行，应该安装哪些 Skill？”主标题。
- 一分钟、无需登录、结果可分享三项承诺。
- 单一主按钮“开始扫描我的职业”。

### 10.2 行业与岗位

- 行业提供搜索、热门入口和完整分类。
- 岗位支持搜索和最多双选。
- 第二岗位被选择时显示“复合职业”提示。

### 10.3 三题微调

- 每屏一题。
- 显示进度。
- 使用与岗位相关的具体工作描述。
- 每题最多选择两项，并明确限制。

### 10.4 结果页

- 顶部显示 AI 职业称号及画像。
- 必装、进阶和能力建议分区。
- Skill 卡片默认简洁，点击展开推荐理由、场景和链接。
- 能力建议使用与真实 Skill 明显不同的视觉样式。

### 10.5 分享卡

- 竖版构图，适合保存和发布小红书。
- 包含职业称号、行业岗位、Top 5 Skill、能力雷达、目录版本和品牌。
- 不包含长链接和安装命令。
- 使用原生 Canvas 生成。

## 11. 离线技术结构

推荐文件结构：

```text
index.html
styles.css
app.js
catalog.js
assets/
```

- `index.html`：单页语义结构与页面容器。
- `styles.css`：视觉、响应式布局和动画。
- `app.js`：状态机、问卷、推荐计算、本地存储和 Canvas 分享卡。
- `catalog.js`：行业、岗位、任务、Skill 与版本信息。
- `assets/`：经压缩的少量本地图标。

不引入框架和第三方运行时。图标优先使用内联 SVG，装饰效果优先使用 CSS，控制包体。

## 12. 数据流与状态

单页状态依次为：

```text
intro → industry → role → question-1 → question-2 → question-3
      → calculating → result → share
```

状态包含：

- 已选行业。
- 已选岗位。
- 三题答案。
- 任务权重向量。
- 推荐结果。
- 目录版本。
- 当前页面。

最近一次结果可写入本地存储。本地存储不可用时，当前会话仍必须完整运行。

## 13. 错误与降级

- 岗位数据不足时退回行业级推荐，并明确提示。
- 真实 Skill 不足时减少真实条目，以能力建议补足。
- 未核验或链接缺失的条目不得进入可获取 Skill。
- 本地存储失败时不阻塞测评。
- Canvas 保存受限时显示全屏图片供用户长按保存。
- 系统开启减少动态效果时跳过强动画。
- 金融、法律、医疗等高风险行业必须声明 Skill 仅辅助工作，不能替代专业判断。

## 14. 首版规模

- 20 个行业大类。
- 80 至 120 个岗位。
- 150 至 200 个任务标签。
- 至少 60 个核验通过的真实 GitHub Skill。
- 约 30 个建议补充能力。
- 每个岗位至少一套完整标准结果。

## 15. 验收标准

- 用户可在 60 秒内完成完整流程。
- 每个推荐均有可理解的个性化理由。
- 同一岗位使用不同答案时，至少三个推荐项或排序发生变化。
- 明显不同的岗位不能产生高度雷同的必装列表。
- 所有 GitHub 链接在数据冻结当天通过自动检查。
- Skill 功能描述均能在 README 找到依据。
- 断网环境完整可用。
- 首次入场动画在目标手机上流畅。
- 完整上传包不超过 2MB。
- 分享卡无中文截断，能够保存。
- 小屏和半屏容器中不存在横向溢出。
- 页面支持系统减少动态效果。
- 不使用“官方认证”“保证提升”等无法证明的宣传。

## 16. 测试范围

- 行业和岗位搜索。
- 单岗位与复合岗位推荐。
- 动态问题及答案限制。
- 权重合并、排序、去重和类别配额。
- Skill 不足时的降级。
- 本地存储关闭场景。
- 分享卡生成、保存和长文本截断。
- 小屏手机、半屏和全屏容器。
- 首次动画、重播及减少动态效果。
- GitHub 链接和证据完整性。
- 构建包体积限制。

## 17. 后续更新

GitHub 目录在制作阶段检索和核验，随后冻结进 `catalog.js`。每次更新目录时提升数据版本、重新执行链接与内容检查，再发布新版本小工具。运行时不声称实时更新。
