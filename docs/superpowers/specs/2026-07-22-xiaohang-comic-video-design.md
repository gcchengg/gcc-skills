# 小航漫改 Skill 设计

## 1. 目标

创建一个名为“小航漫改”的 Codex Skill。它用于批量制作 20–40 秒、9:16 竖屏的中国家庭情感漫画短视频，适配视频号和抖音。

每次运行先给出五个候选主题。用户选择主题后，Skill 生成六幕故事 Markdown，逐幕生成并确认漫画图片，等待用户提供六个本地配音文件，最后按音频真实时长生成 HyperFrames 视频。

Skill 的内部目录名为 `xiaohang-comic-video`，UI 展示名为“小航漫改”。源码先创建在当前仓库的 `xiaohang-comic-video/`，验证后安装或复制到 `~/.codex/skills/xiaohang-comic-video/`。

## 2. 范围

### 包含

- 五个家庭情感候选主题的生成与选择。
- 固定六幕的故事、旁白、字幕、画面和生图提示词设计。
- 原创女孩“小航”的角色一致性管理。
- 逐幕图片生成、字幕预览和人工批准。
- 六段本地配音的发现、时长探测和对应关系校验。
- 基于 HyperFrames 的图片运动、字幕、音轨、转场和 MP4 渲染。
- 四道门禁状态管理和依赖失效处理。
- 分镜、图片、音频和最终视频的确定性校验。

### 不包含

- 自动生成配音。Skill 只输出逐幕语音稿，并等待用户提供本地音频。
- 默认生成背景音乐。BGM 后续可作为可选扩展，首版关闭。
- 线稿逐笔显现或线稿上色动画。
- 自动发布到视频号、抖音或其他平台。
- 成人主角、青春期或成年版小航。小航始终保持 8–10 岁。
- 血腥、创伤性医疗细节、贫困猎奇或以亲情为名的服从式道德绑架。

## 3. 核心工作流与四道门禁

### 门禁 1：主题确认

Skill 生成 `topic-options.md`，其中包含五个明显不同的主题。每个主题必须给出：

- 主题标题。
- 开头冲突。
- 关键生活道具。
- 中段反转。
- 结尾情绪落点。

用户必须明确选择一个主题。未经确认，不得生成正式故事、图片或视频。

### 门禁 2：Markdown 确认

Skill 根据已确认主题生成 `storyboard.md`。文档包含六幕完整内容，并以可直接审阅的方式呈现旁白、字幕和生图内容。

每幕必须包含：

- 剧情作用。
- 8–10 岁小航的第一人称旁白。
- 与旁白一致、适度压缩的 1–2 行中文字幕。
- 建议配音时长。
- 人物、动作、表情、场景和关键道具。
- 镜头景别、构图和字幕安全区。
- 完整生图提示词。
- 画面运动方式。
- 图片确认状态。
- 对应音频文件名。

未经用户批准 `storyboard.md`，不得调用生图工具。

### 门禁 3：图片确认

图片采用两阶段生成：

1. 先生成第一幕，确认本条故事中的角色一致性、父亲形象、环境质感和字幕版式。
2. 第一幕通过后，生成其余五幕。

每幕保存无文字原图和程序叠加字幕的确认图。用户可以批准或仅重做指定场景。已批准版本不得被后续生成覆盖。

生成确认图后，将本地图片链接、当前版本和批准状态回写到 `storyboard.md`，使用户始终能在同一份 Markdown 中对照文字、提示词和实际图片。

只有六幕图片都记录为已批准，才能进入音频门禁。

### 门禁 4：音频就绪

图片全部批准后，Skill 输出六段配音交付清单。用户使用其他 AI 生成配音，并向 Codex提供本地路径。

必须验证：

- 恰好有六个可读取音频。
- 文件与六幕顺序一一对应。
- 不存在空音频或异常静音文件。
- 六段语音加上计划的首尾呼吸和转场后，计算出的成片时长在 20–40 秒内。

验证通过后生成 `audio-manifest.json`。四道门禁全部通过后才能构建视频。

## 4. 单条视频的目录结构

每条视频使用独立项目目录：

```text
videos/xiaohang/<topic-slug>/
├── topic-options.md
├── storyboard.md
├── status.json
├── images/
│   ├── scene-01-source-v1.png
│   ├── scene-01-preview-v1.png
│   └── ...
├── audio/
│   ├── scene-01.mp3
│   ├── scene-02.mp3
│   └── ...
├── audio-manifest.json
├── hyperframes/
│   └── index.html
└── renders/
    └── final.mp4
```

图片文件必须版本化。`status.json` 只记录明确批准的图片版本。

## 5. 六幕叙事结构

每条视频固定六幕：

1. **扎心冲突**：第一句建立误解、冲突或带有争议的判断。
2. **日常证据**：通过生活场景强化小航最初的看法。
3. **异常细节**：出现被忽略的动作、物件或不合常理的细节。
4. **发现真相**：小航理解父亲真正承受或付出的东西。
5. **情绪行动**：用具体行动表达理解，不依赖哭喊或抽象说教。
6. **克制余韵**：用一句适合传播但不过度煽情的话收束。

语言必须符合 8–10 岁儿童认知。避免成年人的抽象术语、复杂价值判断和故意制造内疚的表达。

## 6. 主题范围与情绪边界

候选主题可以覆盖：

- 父亲能力有限，但一直托举孩子。
- 孩子误解父亲，后来从生活细节发现真相。
- 父亲生病、衰老或离别前的克制瞬间。
- 父亲不善表达，却始终用行动说爱。
- 普通家庭里的陪伴、亏欠、和解与成长。

叙事不得把“父母牺牲”转化为“孩子必须服从”的道德结论。涉及疾病或临终时，不展示创伤性医学细节；通过握手、药袋、旧衣、灯光、陪伴动作等克制表达。

## 7. 原创角色与视觉规范

### 小航

- 永久年龄：8–10 岁。
- 中国女孩。
- 微卷深棕色中短发。
- 湖蓝色小船发卡。
- 温暖棕色杏眼，不使用巨大纯黑圆眼。
- 奶油色上衣和湖蓝背带裙为基础造型。
- 可以随季节和场景更换服装，但发型、发卡、眼睛、脸型和基础色保持稳定。

### 陪伴角色

一只小黄混种犬，一侧耳朵下垂。它是可选的陪伴型角色，不要求每幕出现。

### 父亲

父亲的年龄、职业、服装和生活状态可以随主题变化。形象应普通、体面、可信；不使用污名化贫困、夸张衰老或猎奇疾病特征。

### 固定画风

- 原创复古中国儿童漫画。
- 暖色旧纸张纹理。
- 粗细变化的炭笔墨线。
- 低饱和彩铅填色。
- 奶油白、湖蓝、赭黄、深棕为基础色。
- 温暖灯光与克制的生活细节。
- 每幕必须使用不同构图，不得通过裁切、镜像或缩放复用图片充数。

### 构图

- 画幅固定为 9:16、1080×1920、30fps。
- 为 1–2 行字幕保留平台安全区。
- 六幕至少包括远景、双人镜头、道具特写、反应镜头和结尾宽景。
- 人物动作和生活道具承担叙事，不能只靠字幕说明。

参考图片只提供高层视觉启发。不得复制其黑色齐耳短发、红色连帽衫、红色短裤、黑猫、巨大纯黑眼睛、角色比例、完整构图或文字排版组合。

## 8. 图片生成与确认

使用可用的 `imagegen` 能力逐幕生成图片。每个提示词包括：

- 小航固定角色信息。
- 当前场景中的人物、动作、表情和道具。
- 镜头景别和画面层次。
- 字幕安全区。
- 固定画风和配色。
- 本幕必须避免的错误。

第一幕使用已确认的小航基准图作为角色参考。后续场景同时参考基准图和已批准的前一幕，以提高角色一致性。

原始生图不得包含文字。准确字幕通过 HTML/CSS 叠加生成 `scene-XX-preview-vN.png`，从而避免中文错字。字幕修改只重新生成确认图，不重新生图。

## 9. 音频和时间轴

用户提供：

```text
audio/scene-01.mp3
audio/scene-02.mp3
audio/scene-03.mp3
audio/scene-04.mp3
audio/scene-05.mp3
audio/scene-06.mp3
```

每幕时长以对应音频真实时长为核心，并在场景内部添加少量首尾呼吸时间。不得通过裁切旁白强行满足预估时长。若六幕音频与呼吸、转场合计后超出 20–40 秒，停止构建并要求调整配音，而不是压缩或截断声音。

`audio-manifest.json` 保存文件路径、原始音频时长、呼吸时间、对应场景、时间轴起点和终点。视频总时长必须保持在 20–40 秒。

## 10. 视频表现

视频不使用线稿显现或逐渐上色。每幕采用完整漫画原图，通过以下方式增加运动：

- 缓慢推近或拉远。
- 水平或垂直轻微平移。
- 有明确前中后景时采用轻量视差。
- 纸张擦拭、漫画格切换或柔和叠化转场。

字幕使用 HTML/CSS 叠加，与图片确认稿保持一致。字幕不得遮挡小航面部、父亲关键动作或核心道具，并避开视频号和抖音界面区域。

首版默认不添加 BGM。

## 11. 状态与依赖失效

`status.json` 保存四道门禁状态和批准资产版本。

依赖失效规则：

- 更换主题：故事、图片、音频和视频状态全部失效。
- 修改旁白：对应图片字幕预览、音频和视频状态失效。
- 仅修改字幕断行或样式：对应图片预览和视频状态失效，原始生图与音频保持有效。
- 更换图片版本：对应图片批准和视频状态失效；旁白与音频保持有效。
- 更换音频：音频清单和视频状态失效。

脚本必须拒绝在前置门禁未通过时执行后续步骤。

## 13. 技术职责

- `imagegen`：逐幕生成原创漫画图片。
- HTML/CSS：叠加准确中文字幕并生成确认稿。
- FFprobe：探测六段本地配音时长。
- HyperFrames：组织场景、图片运动、字幕、音轨和转场。
- FFmpeg：检测最终分辨率、时长、音频流和黑帧。
- Python 脚本：项目初始化、格式验证、门禁状态、清单生成和视频装配。

## 14. 错误处理

- 文档缺少六幕、字幕过长或音频映射错误时，给出精确场景编号和修复原因。
- 图片生成失败时保留已批准场景，只重试失败场景。
- 不覆盖旧图片或旧成片；所有重做图片和最终渲染使用版本化文件名。
- HyperFrames 检查失败时停止渲染，修复对应 Composition 后重新运行失败检查。
- 最终视频出现黑帧、缺少音频流、字幕溢出或总时长超限时不得交付。

## 15. 测试策略

### Skill 行为基线

先在不加载新 Skill 的情况下运行代表性请求，记录代理是否：

- 未经主题确认直接写完整故事。
- 未经 Markdown 批准直接生图。
- 图片未全部批准就索要或使用音频。
- 音频不完整时仍生成视频。

加载新 Skill 后重放相同请求，确认代理严格停在正确门禁。

### 确定性脚本测试

- 六幕数量、旁白和字幕必填项。
- 字幕行数、长度和安全区约束。
- 门禁跳步拒绝。
- 内容修改后的状态失效。
- 缺图、图片版本和批准版本校验。
- 缺音频、重复音频、音频顺序和总时长校验。
- HyperFrames 输出包含六幕、六段音轨和正确总时长。
- 最终视频为 1080×1920、30fps、有音频流且无明显黑帧。

## 16. 验收标准

- Skill 能被家庭情感漫画、父女故事、亲情鸡汤和小航漫画视频等请求正确触发。
- 每次先提供五个主题，未经选择不继续。
- 每条故事固定六幕、20–40 秒、第一人称旁白。
- 每幕具有 1–2 行准确字幕和完整生图说明。
- 图片必须逐步确认，旧批准资产不会被覆盖。
- 用户提供的六段本地配音决定真实时间轴。
- 四道门禁通过前不能生成视频。
- 最终 MP4 适配视频号和抖音，尺寸、时长、音频、字幕和黑帧检查全部通过。
