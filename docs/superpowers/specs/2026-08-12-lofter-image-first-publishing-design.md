# LOFTER 图文首图发布设计

## 目标

`lofter-x-anime-hotspot` 发布图文时，LOFTER 正文编辑器的第一个内容节点必须是已批准清单中的封面图。正文文字和其他图片只能出现在封面图之后，使文章首屏先呈现视觉钩子。

## 本地预览

- `preview.html` 的公开阅读顺序固定为：封面图、正文、正文配图。
- 封面图在预览中不得仅出现在独立的媒体清单区域；它必须出现在文章正文之前。
- 正文图按上传清单顺序放在正文之后；不改变原有媒体账本、摘要值或发布身份。

## LOFTER 表单填写

1. 从锁定的 `upload-manifest.json` 读取角色为 `cover` 的媒体，且仅允许一张封面。
2. 进入已登录的 Codex 应用内 LOFTER 编辑器后，先上传封面图。
3. 上传返回后检查编辑器的第一个有效内容节点。只有该节点是图片且能对应封面上传动作，才允许继续填写正文。
4. 填写正文后，再按清单顺序上传零至两张正文图。
5. 如果 LOFTER 将封面插至文末，必须通过页面支持的编辑操作将其移动到顶部；无法明确完成或确认时停止，不进入最终提交。
6. 浏览器重连或草稿恢复后重新检查首节点，不依赖重连前的内存状态。

## 最终平台预览证据

- 最终核对必须确认标题、完整正文、标签、图片数量和图片顺序与锁定清单一致。
- 额外要求 `first_content_is_cover: true`；该字段只能来自页面实际观察，不能根据上传顺序推断。
- `publication_gate.mark_form_filled` 只有在首节点确认通过后才能将运行转入 `publishing`。
- `确认最终提交` 仍是唯一允许点击发布按钮的第二确认。

## 失败处理

- 封面上传失败、首节点不是图片、图片顺序不明、编辑器重置或草稿恢复结果有歧义时，保留草稿并暂停。
- 不为修复顺序而重复上传同一张图片；先检查当前页面，再决定移动、删除或重新填写。
- 未完成首图核对时不得声称表单已准备完成。

## 验收标准

- Skill 协议明确要求“封面图 → 正文 → 正文图”。
- 本地预览在正文前渲染封面。
- 发布门禁拒绝缺少 `first_content_is_cover: true` 的平台预览证据。
- 浏览器发布协议要求上传封面后立即核对首节点，并在恢复草稿后重新核对。
- 现有媒体校验、登录恢复、授权确认和最终提交门禁保持有效。
