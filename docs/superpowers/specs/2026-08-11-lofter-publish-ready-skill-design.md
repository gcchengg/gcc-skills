# LOFTER 热点图文生成与发布工作流设计

**日期：** 2026-08-11  
**状态：** 已由用户确认  
**涉及 Skill：** `lofter-x-anime-hotspot`

## 1. 目标

将现有的热点研究与人工审核包生成器升级为一个单 Skill、双阶段的内容工作流：

1. 每次调用默认研究 X 与 LOFTER 热点，自动选择一个主题，生成一套可预览的 LOFTER 图文成品。
2. 用户在本地预览中复核素材授权并提出修改。
3. 用户明确确认后，Skill 恢复该次运行，通过 Codex 内置浏览器填写 LOFTER。
4. 到达 LOFTER 最后提交按钮前再次确认，第二次确认后才允许正式发布。

默认产出为每次一篇精品图文。工作流保留现有五 IP 池、热点评分、授权绑定及同人文研究门槛。

## 2. 方案选择

采用“单 Skill 双阶段状态机”。生成、修改、发布均由 `lofter-x-anime-hotspot` 完成，通过持久化运行目录恢复上下文。

未采用的方案：

- 拆成生成与发布两个 Skill：边界清楚，但用户需要在两个入口间切换，并手工传递运行目录。
- 单次调用持续等待确认：实现简单，但任务中断、浏览器登录或隔日修改时难以恢复。

单 Skill 状态机最符合“每次调用自动产生成品，并在确认后继续发布”的使用方式。

## 3. 运行目录与状态机

每次新草稿创建唯一运行目录：

```text
lofter-x-anime-hotspot/runs/20260811-143000-topic-name/
├── status.json
├── hotspot-analysis.json
├── article.md
├── titles-and-tags.md
├── preview.html
├── publication-order.md
├── sources/
│   └── media-ledger.json
├── original-media/
└── generated-media/
```

运行状态如下：

```text
researching
  → draft_ready
  → authorization_review
      → revisions_required → authorization_review
      → approved
          → publishing
              → published
```

`status.json` 至少记录运行 ID、当前状态、主题、内容形态、时间窗口、文件清单、素材复核状态、两次发布确认、错误信息、LOFTER 文章地址及时间戳。

状态转换必须显式校验，禁止跳过授权复核或确认门禁。任务中断后再次调用时，Skill 根据运行 ID 或最近的未完成运行继续处理，不重新选题。

## 4. 首次调用流程

### 4.1 热点研究

1. 检索 X 与 LOFTER 最近 24 小时的二次元热门内容。
2. 若数据量、可信来源或可用素材不足，自动扩大至最近 72 小时。
3. 从固定五 IP 池及不限量候选话题中评分。
4. 评分综合热度、增长速度、LOFTER 适配度、素材丰富度、同质化程度和风险，而非只取转发量最大者。
5. 若没有达到质量门槛的主题，停止成稿并报告缺少的数据，不填充低质量内容。

### 4.2 内容形态选择

Skill 根据热点特征自动选择：

- 有明确事件、争议或趋势：热点分析。
- 角色关系或世界观讨论突出：轻量同人文。
- 高质量图片集中、文字信息较少：视觉策展。

同人文继续遵守现有五项研究检查、观察来源及质量门槛。

### 4.3 默认成品

每次生成：

- 一篇约 800–1500 字、可直接用于 LOFTER 的中文正文。
- 三个备选标题。
- 8–12 个 LOFTER 标签。
- 一张封面及最多两张正文图。
- 图片插入位置和发布顺序。
- 浏览器可查看的 `preview.html`。
- 热点分析、来源台账和授权复核清单。

正文不逐条翻译或简单拼接 X 帖子，而是提炼共同趋势、补充背景并形成完整观点。默认公开披露为：

```text
图像经授权使用，含AI辅助创作｜#AI辅助#
```

内部授权证据和证据路径不得写入公开正文。

## 5. 素材处理与授权复核

### 5.1 候选素材

研究阶段允许先选择合适的 X 图片进入内部预览，不在选图前逐张询问用户。每张素材必须记录：

- 原帖 URL。
- 作者账号。
- 抓取时间。
- 帖子和媒体标识。
- 本地文件及校验信息。
- 使用方式：原图转载、AI 改编或原创生成。
- 当前复核状态。

未完成用户最终复核的素材只能用于本地预览，不得上传到 LOFTER。示例授权记录继续维持 `example_only` 和 smoke-only 约束，不得成为真实发布凭据。

### 5.2 无授权素材替换

用户可以用自然语言指出无授权素材，例如“第 2 张没有授权”。Skill 应：

1. 将该素材标为不可发布。
2. 生成构图和表达明显不同的原创替代图，而不是继续改编无授权图。
3. 只修改受影响的图片说明、正文引用和发布顺序。
4. 保留其他已确认内容。
5. 重新生成预览并回到 `authorization_review`。

原图、AI 改编图和原创生成图必须分开存储和标记，避免发布时混用。

## 6. 预览与修改交互

预览必须展示：

- 完整图文排版。
- 选题理由和热点依据。
- 每张图片的编号、来源和使用方式。
- X 原图、AI 改编图或原创生成图标记。
- 标题、标签、正文和发布顺序。
- 明确状态提示：`等待授权复核，尚不可发布`。

用户可用自然语言提出局部修改，例如更换图片、调整文风、排除 CP、重写标题或全部重做配图。Skill 从运行目录恢复状态，并将修改限制在相关内容上。

## 7. 双重确认发布流程

发布属于对外操作，必须经过两次独立、明确的确认：

### 7.1 第一次确认

用户明确回复“确认发布”后：

1. 校验正文、图片文件、素材复核状态、来源台账和披露文字。
2. 状态从 `authorization_review` 变为 `approved`。
3. 使用 Codex 内置浏览器打开 LOFTER。
4. 如未登录，停在登录页面，由用户完成登录。
5. 自动填写标题、正文和标签，并按既定顺序上传图片。

没有第一次确认时，不得进入 LOFTER 填写阶段。

### 7.2 第二次确认

完成填写后，Skill 停在 LOFTER 最后提交按钮前，向用户展示平台内最终预览。只有用户再次明确确认后，才允许点击提交按钮。

发布成功后记录：

- LOFTER 文章 URL。
- 发布时间。
- 最终正文、标题和标签。
- 最终媒体清单和来源台账。
- 发布结果证据。

随后状态变为 `published`。

## 8. 安全与异常处理

- 不保存 X 或 LOFTER 的账号密码、Cookie 或验证码；登录状态仅由内置浏览器管理。
- LOFTER 出现验证码、风控或登录要求时暂停，由用户处理。
- 图片下载、生成或上传失败时保持草稿状态，并列出失败项。
- 授权复核不完整时禁止进入 LOFTER 填写阶段。
- 页面结构变化时停止，不猜测关键按钮。
- 发布结果不明确时先检查个人主页或草稿箱，不自动重复点击，避免重复发布。
- 发布成功后保留完整本地归档，用于复盘和防止重复选题。

## 9. 实现范围

升级现有 Skill，增加：

- 热点搜索与自动选题编排。
- 可发布中文正文生成。
- X 候选素材获取与来源台账。
- 封面和正文配图生成，以及无授权素材替换。
- 运行目录、状态机和中断恢复。
- HTML 图文预览。
- 自然语言驱动的局部修改。
- LOFTER 内置浏览器填写和双重发布确认。
- 发布结果归档。

现有评分、授权和包结构能力应复用，不能降低当前 fail-closed 安全性。

## 10. 验收标准

1. 一次调用可生成一个完整图文预览包。
2. 24 小时素材不足时自动扩大至 72 小时。
3. 能按热点特征选择分析、同人文或视觉策展。
4. 用户指出某张图片无授权后，仅替换相关图片和文案。
5. 未经第一次确认不能进入 LOFTER 填写流程。
6. 未经第二次确认不能点击最终提交按钮。
7. 登录、验证码、上传失败及发布结果不明确时能安全暂停。
8. 中断后再次调用可恢复原运行，不重新生成。
9. 发布成功后保存文章 URL、最终内容和媒体清单。
10. 现有五 IP 池、热点评分、授权绑定和同人文研究门槛继续有效。
11. 状态机、授权门禁、预览产物及恢复逻辑具备自动化测试。
12. 浏览器发布使用模拟页面测试，并在真实页面验收时停在最终提交前。

## 11. 非目标

- 不进行无人值守自动发布。
- 不绕过登录、验证码、平台风控或授权校验。
- 不把候选素材默认视为已授权发布素材。
- 不在发布失败或结果未知时自动重试提交。
- 不在本次升级中新增第二个独立发布 Skill。
