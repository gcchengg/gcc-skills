# 小红书文案契约

## 内容重心

正文的多数篇幅用于说明 Skill 本身，而不是行业感慨或岗位焦虑：

1. 钩子：这个 Skill 解决哪件反复工作。
2. 一句准确、可验证的定义。
3. 3–6 项具体能力、输入和输出。
4. 指令、资源、工具、校验和交付机制。
5. 与相邻工具或普通 Prompt 的区别。
6. 一个最小真实案例：可复述的调用方式和预期产物。
7. 安装与调用：只使用仓库核验过的命令。
8. 边界与风险。
9. 什么样的人需要：先写工作症状，再写岗位。

## 标题

提供 1 个推荐标题和 3 个备选标题，每个标题最多 20 个 Unicode 字符，字母、数字、标点和空格均计入。推荐标题让用户同时看见“对象＋价值或反差”，适合手机首屏；不使用虚假排名、保证效果或无证据的“全网第一”。

可用结构：

- `{岗位}别再{重复劳动}了！这个 Skill {核心结果}`
- `这个 GitHub Skill，把{复杂任务}直接{可见结果}`
- `{热度证据}的{类别} Skill，到底强在哪？`
- `一句话{结果}，{岗位}该装这个 Skill 吗？`

## 两份文案

- `小红书文案.md`：推荐标题、备选标题、结构化正文、带半角 `#` 的话题标签、来源与核验记录。
- `发布粘贴版.txt`：无 Markdown 标题符号、无反引号、无来源脚注标记；正文可直接粘贴。

话题默认 8–12 个，覆盖品类词、任务词、岗位词和 Skill 专属词。`小红书文案.md` 的话题行固定写成 `\#AI工具 #AgentSkill #GitHub开源`：仅在行首第一个井号前加一个反斜杠，使 Markdown 预览显示为普通话题行；`发布粘贴版.txt` 固定写成 `#AI工具 #AgentSkill #GitHub开源`，不带反斜杠，可直接粘贴发布。不得输出裸关键词、全角 `＃`、占位符或二次加工要求。不要声称批量粘贴后平台一定会把它们识别为可点击话题。

## 长度限制

- `发布粘贴版.txt` 第一行是推荐标题，最多 20 个字符。
- 第一行之后的全部发布内容最多 900 个 Unicode 字符；换行、标点、空格和话题标签均计入。
- `小红书文案.md` 中 1 个推荐标题和 3 个备选标题也都必须在 20 字符内；正文应与粘贴版保持同一精简版本，来源与核验记录不属于发布正文。
- 完成前运行 `python3 scripts/check_copy_limits.py <主题目录>`，超限时先删减铺垫和重复表达，不删 Skill 定义、核心能力、最小案例、适合人群及必要风险。
