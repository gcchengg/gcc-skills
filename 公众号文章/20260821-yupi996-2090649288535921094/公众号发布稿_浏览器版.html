AI 编程工具的竞争，正在从“谁的模型更强”走向另一个问题：谁能让 Agent 更容易被改造、被观测、被控制？

DeepSeek Harness，简称 DSH，是 DeepSeek 开源的 Agent 运行环境。它与 Claude Code、Codex 一样都可以承载 AI 编程工作，但起点很不一样：它把“一切皆插件”当成了架构原则。

模型适配器、工具注册、会话日志、Agent 循环，甚至 Web 界面，都可以被 Cordis 元框架中的插件替换或扩展。换模型、加工具、改交互，很多时候只需改配置，不必修改核心源码。

这种开放性很迷人，也容易制造一个错觉：只要安装更多插件，Agent 就会自动变强。

事实恰好相反。插件会补能力，也会增加权限、依赖、上下文、兼容性和维护成本。所以这篇文章不是要你一口气装完 16 个插件，而是帮你搭出一张地图：什么问题值得用插件解决，什么时候应该克制。

一、先搞清楚：你缺的是能力，还是界面？

从使用价值看，DSH 社区插件可以被分为四类：

  1. 能力插件：让 Agent 多一双眼、多一个搜索源、多一只可操作浏览器的手。
  2. 编排插件：让多个 Agent 分工，把一个任务拆成可并行的子任务。
  3. 工作台插件：管理任务、Git、文件、终端、上下文和远程会话。
  4. 体验插件：改造皮肤、加入桌宠和互动彩蛋，功能价值不高，但会提高社区传播和使用意愿。

安装前先问自己：我现在的阻力究竟是“Agent 做不了”，还是“我用起来不顺手”？前者选能力扩展，后者选界面与工作流增强。不分青红皂白全部安装，最后往往会变成“功能很多，出错时不知道是谁干的”。

二、三种找插件的方式，信任等级完全不同

寻找 DSH 插件有三条常见路径。

GitHub 主题页：最快，但不代表经过审核

开发者可以给仓库打上 dsh-plugin 标签，新项目通常很快就能被发现。但这只是一个自申报标签，不等于官方推荐，也不等于做过代码审计。

Awesome 清单：更好浏览，但仍是社区筛选

社区维护的 Awesome DSH Plugin 会按用途归类，很适合快速了解生态。但“被收录”与“经过安全验证”是两件事。

dsh-market：体验最像应用商店

dsh-market 把浏览、搜索和安装入口放进 DSH，还能根据已安装插件继续推荐。不知道项目名时，可以直接搜“远程”之类的功能词，找到 dsh-pocket 这类项目。

安装也不一定要自己手敲每条命令。可以把 GitHub 仓库地址给 DSH，让 Agent 阅读 README、找到安装方法并执行，完成后按提示重启 dsh web。

但要注意：让 AI 替你执行安装，只是省掉手工操作，不是省掉安全审核。 README 可以解释安装方法，却不能替你证明代码安全。

三、给 Agent 补眼睛、搜索和双手

ModLens：把图像翻译成模型能理解的上下文

在纯文本模型链路中，直接粘贴截图，Agent 并不会自动获得视觉能力。ModLens 的思路是加一个视觉转译层：图片先交给 Qwen 等外部视觉模型，解析出 OCR 文字、布局区域、元素位置和语义，再把结构化 JSON 作为上下文交给 DeepSeek 推理。

它与普通 OCR 的差异，是尽量保留“字在哪里、元素如何组织、画面表达什么”。对前端开发尤其实用：页面做完后粘贴截图，让 Agent 检查布局和还原度。

代价也很明显：图片会被发送到额外的视觉模型服务，敏感截图、内部后台和用户数据必须先确认传输边界。

ModSearch：扩大信息源，不是给搜索结果盖章

ModSearch 可以接入 Firecrawl、Tavily、Exa 等搜索源，并扩展 Twitter/X 内容检索。它适合需要深度全网调研的任务，弥补 DSH 原生搜索范围有限的问题。

即使没有配置所有 API Key，某些基础搜索也可能找到社交网络原帖；但要稳定使用完整能力，仍需配置对应服务的凭证。更重要的是，搜到原帖不等于内容可信，二次核验仍然是必需步骤。

dsh-browser：复用真实 Chrome 的登录态

dsh-browser 不是再开一个无头浏览器，而是连接你正在使用的 Chrome 标签页，复用 Cookie、Session 和登录状态。

它由 DSH 桥接插件和 Chrome MV3 扩展组成，两端通过本地 WebSocket 通信。扩展把网页转换成带有可交互元素编号的结构化文本，模型不必仅靠截图猜测页面，就能读取、点击、输入和跳转。

安装比普通插件多一步：除了插件本体，还需在 chrome://extensions 手动加载本地扩展，看到 Connected 后才算连通。

它可以在 GitHub 中找置顶仓库并进入详情，也可以在已登录的 X 页面中输入搜索词、切换最新结果。点击、输入和跳转等动作默认需要用户确认；当用户手动切换标签页时，它也会询问是留在原页面，还是跟随当前页面。

一个实用细节是：它默认绑定当前活动标签页。如果直接在 DSH 页面要求打开 GitHub，对话页本身可能被导航走。更顺手的方式是先打开目标网站，再从 Chrome 侧边栏发起对话。

ModSearch 与 dsh-browser 很容被混为一谈。前者解决“去哪里找信息”，后者解决“如何在一个已登录的网站里完成动作”。如果你只需要调研，先用搜索；如果需要填表、查后台或处理带登录态的页面，才考虑浏览器操作。

四、Agent Teams：多 Agent 不是人海战术

Agent Teams 会创建一个 Captain 节点和多个成员 Agent。Captain 负责拆任务、分工和汇总，成员则各自处理不同方向。

比如检查一个前端项目，可以让三名成员分别检查界面、性能和工程质量，右侧活动面板会显示他们同时工作，最后由 Captain 生成统一报告。

这支团队完成一次任务后不会立即消失。后续可以只指定某一个成员继续处理，例如只让 frontend 成员研究 WebGL 降级，其他成员不会被重复调度。

多 Agent 有两个成本：调度时间和 Token 消耗。只有当任务可以按専业方向真正拆开，并且结果需要汇总时，它才比单 Agent 更合适。一个人五分钟能做完的事，就别为了热闹召集一支队伍。

五、把 DSH 变成工作台：七个插件各有边界

dsh-market：插件发现层

它解决的是“找不到”和“记不住名字”，不是安全审计。推荐结果仍应回到仓库更新、Issue、权限和源码上判断。

dsh-web-ui：功能最齐的工作台

dsh-web-ui 集成任务看板、Git 管理、工作台、状态信息、皮肤主题和桌宠。任务可以从建立一直跟踪到完成，还能跳回实际执行任务的 DSH 会话。

Git 部分可以搜索、切换和新建分支，并把提交历史画成分支图谱。全家桶版还会安装 dsh-better-sidebar，在右侧加入类似 VS Code 的工具栏；文件列表中可以用 @文件 直接引用当前文件，不必手动复制路径。

它适合把 DSH 当主力工作环境的人，但功能越多，对 DSH 版本变化的敏感度也越高。

DSH-better-sidebar：只解决侧边栏

如果你只想在右侧集中查看文件树、终端和 Git 状态，DSH-better-sidebar 比全家桶更轻。它没有任务看板、皮肤中心和桌宠，因此维护面也更小。

dsh-context：给长会话做 Token 体检

长会话变慢时，很难凭感觉判断是历史消息、文件还是工具结果占满了上下文。dsh-context 会展示当前上下文的类别、Token 比例和变化记录，帮你决定该清理什么，而不是动不动重开会话。

dsh-TUI：终端爱好者的全屏界面

dsh-TUI 提供类似 Claude Code 的终端交互，底部实时显示模型、推理强度和上下文占用率。但它对界面和交互改动较大，而 DSH 本身仍在快速迭代。新手过早安装，遇到接口变更时会很难判断问题来自核心还是 TUI。

dsh-genui：让回答变成可交互界面

dsh-genui 可以把回答渲染成卡片、图表和选项按钮，而不只是文字与 Markdown。用它生成“AI 编程工具对比面板”时，信息卡和柱状图可以直接出现在对话中，而且是真正可交互的组件。它适合数据展示、方案对比和需要人机选择的场景。

dsh-pocket：手机变成远程控制台

dsh-pocket 会生成二维码，让手机浏览器查看电脑上 DSH 的运行状态和继续发送消息。

局域网模式需要手机和电脑在同一 Wi-Fi；公网模式则通过 Cloudflare Quick Tunnel 建立临时通道，不需要额外购买服务器。第一次访问需输入密码，每次重新开启公网访问时密码会更换；流式输出通过 WebSocket 在电脑和手机之间传递。

它很适合在 Agent 跑长任务时离开电脑查看进度，但二维码、公网地址和密码都不能随意分享。DSH 能读写本机文件和代码，这不是一个普通网页的暴露面。

六、“没什么用”的插件，也在塑造生态

技术社区很少只靠实用功能生长。一些看似离谱的插件，反而在降低参与门槛，让更多人愿意截图、分享和二次创作。

dsh-deep-whale：鲸鱼娘主题

它会把整个 Web 界面换成鲸鱼娘风格。它不增加 Agent 能力，却非常适合形成可传播的视觉标识。

whale-girl：更像 QQ 宠物的桌宠

whale-girl 不只显示任务状态，还有等级、投喂和玩耍等互动。Agent 思考时它会歪头，等待时打哈欠，完成任务后欢呼，长时间空闲则睡觉。相比之下，dsh-web-ui 自带的桌宠更像工作状态提示器。

dsh-liang-skin：把推理强度做成“滑动变祖器”

拖动推理强度滑块时，人物会从“梁子”逐渐进化到“梁祖”。它几乎完全属于网络梗式创意，但也说明 DSH 的界面是可被社区深度改造的。

dsh-deepcel：把 DSH 伪装成 Excel

安装后，页面会变成经典表格界面。它既可以让 Excel 重度用户觉得亲切，也是一种极具社交传播力的“摸鱼皮肤”。

dsh-ads：让 2005 年式弹窗广告重返 AI 时代

信息流广告、弹窗、假杀毒、假游戏和花哨横幅都能被塞进 DSH。这显然不会提高生产力，但它将“一切皆插件”推到了一个非常彻底的程度。

这些整活插件不必被当成无用噪音。一个可被创作者玩起来的工具，才容易形成真正的社区。但在生产环境中，这类主题与功能插件应尽量隔离，别让情绪价值变成兼容性负担。

七、安装前先过六道门，比收藏插件名单更重要

DSH 仍处于快速迭代的开发者预览阶段。社区插件的发布速度很快，但兼容性、权限边界和维护周期未必跟得上。安装之前，建议固定检查六件事：

  1. 来源：作者身份、仓库历史、最近更新和 Issue 是否真实？
  2. 权限：它能读哪些文件，能否调用 Shell，能否操作浏览器或网络？
  3. 数据去向：截图、代码、会话和 Token 会不会被发往外部服务？
  4. 版本：它支持哪个 DSH 版本，依赖是否锁定，最近是否还在维护？
  5. 可回滚：安装前是否已用 Git 保存当前可运行状态，出问题能否快速回到上一版？
  6. 真需求：它是在解决一个高频摩擦，还是只因为截图好看？

浏览器、Shell、本机文件和公网远程插件应被视为高风险类别。它们的价值很高，但一旦权限被滥用，影响也不只局限在 DSH 界面里。

此外，只安装有刚需的插件，并用 Git 管理本地 DSH 配置。当某个插件与新版本不兼容，导致 Web 无法启动时，可回滚的环境比任何排错技巧都更值钱。

八、给不同用户的最小安装组合

与其复制一份“全家桶”，不如从最小组合开始。

前端开发者

ModLens + dsh-browser + dsh-context。一个理解页面截图，一个验证真实网页交互，一个防止长会话上下文失控。

深度调研用户

ModSearch + dsh-context。先扩展信息源，再监控搜索结果和工具输出对上下文的占用。如果真的要操作登录网站，再加 dsh-browser。

大型项目或代码审查

Agent Teams + dsh-web-ui。用团队分角色，用任务看板和 Git 图谱管理执行过程。如果不需要看板和主题，把全家桶换成 DSH-better-sidebar 更轻。

长时间运行 Agent 的用户

dsh-pocket + dsh-context。一个让你离开电脑查看进度，一个帮你提前发现上下文即将触顶。开启公网通道时，必须把地址和密码当成敏感凭证。

只想先体验 DSH

先不安装任何大型插件。用原生功能跑几次真实任务，记录自己最频繁遇到的摩擦，再按需补一个。这比跟着截图安装十几个更容易建立可控环境。

结语：插件生态的价值，是让 Agent 工作方式可编辑

DeepSeek Harness 现在最吸引人的地方，不是原生功能已经比所有成熟工具都完整，而是它把 Agent 的运行方式打开给了社区。

视觉理解、全网搜索、真实浏览器、多 Agent、任务看板、Git、上下文体检、生成式 UI、手机远程，都不再只能等官方排期。甚至一个鲸鱼娘、Excel 皮肤或复古弹窗广告，都能成为检验插件系统表达力的实验。

但开放性从来不是免费的。每多一个插件，就多一份依赖、一组权限和一个可能的故障点。

所以，真正成熟的 DSH 玩家不是安装数量最多的人，而是最清楚自己为什么安装、授予了什么权限，以及出问题时如何回滚的人。
