# 正文

最近发现一个很适合架构师、开发者和技术产品经理的 Agent Skill：**Archify**。

它不是给 Mermaid 换皮，也不是让 AI 随便画一张“看起来像架构图”的图片。

Archify 的作用，是把代码库或一段系统描述转换成**可以校验、继续修改、交互查看和导出的系统地图**。

## 它能生成什么？

- 架构图：看清组件、服务、存储和系统边界
- 工作流图：看清参与者、执行顺序、分支和异常
- 时序图：看清调用方、返回值和交互时机
- 数据流图：看清数据来源、转换过程、存储位置和敏感边界
- 生命周期图：看清状态、事件、重试、等待和最终结果

## 它和普通 AI 画图有什么不同？

普通方式往往是：输入一句话，得到一张图。图画错了，只能继续用语言反复修。

Archify 中间多了一层结构化过程：

1. Agent 先把系统整理成带类型的 JSON 结构；
2. 渲染器根据结构生成图，而不是自由发挥；
3. 交付前检查结构、布局、路径和标签；
4. 校验失败时返回具体问题，不直接拿错误结果覆盖成品；
5. 修改时可以只调整指定节点，尽量保持其他结构稳定。

这意味着它追求的不只是“图好看”，还要让图中的节点和关系经得起检查。

## 一个具体例子

你可以直接告诉 Agent：

“画出浏览器访问 API 的过程。先查询 Redis；缓存未命中时，再回退到 PostgreSQL。”

Archify 会把这句话转换成有明确节点、主路径和回退路径的系统地图。

除了静态图片，它还能生成自包含 HTML，并支持 PNG、SVG、WebM 和分享卡等导出形式。图中的节点可以搜索，也可以查看上游、下游和指定路径。

## 怎么安装？

全局安装：

`npx skills add tt-a1i/archify -g`

不安装先试用：

`npx skills use tt-a1i/archify@archify --agent codex`

安装后可以这样对 Agent 说：

“分析这个代码库，然后使用 Archify 创建一张高层运行架构图。展示 8—12 个核心组件、一条主要路径、外部依赖和信任边界。”

## 什么样的人需要它？

- 每次开会都要重新解释系统结构
- 架构图修改几次以后就和真实系统对不上
- 需要把代码和技术方案讲给非技术同事
- 需要在评审前检查路径、边界和依赖关系
- 希望架构图能跟着项目继续维护，而不是画完就失效

对应岗位通常是：软件架构师、开发者、技术产品经理和解决方案顾问。

但也要注意：它不是通用绘图软件，也不会自动证明线上系统一定按图运行。安装第三方 Skill 前，仍然要检查源码、权限、依赖和网络行为。

AI 时代，真正值得沉淀的不是一句 Prompt，而是一整套可以反复执行、检查和改进的工作方法。
