# image2 提示词

通用要求：所有图片均为 3:4 小红书竖版，建议 3072x4096，high quality，PNG，4K ultra high resolution。整体为高级科技产品教程 UI，浅灰白背景，干净网格、细线框、模块卡片、流程箭头、代码块、控制台面板。中文文字要少而大，标题清晰，模块标签清晰，不使用密集长段文字。避免廉价海报、赛博朋克霓虹、花哨贴纸、拥挤小字、模糊中文。

## 01 封面

生成一张小红书 3:4 竖版科技教程封面图，主题是“Claude Code 动态工作流”。画面中心是一个精致的 workflow 控制台 UI，像高级开发者工具仪表盘，中央模块写“动态工作流”，向外连接多个子 agent 节点：研究、编码、验证、总结、排序。整体风格参考 Linear、Notion、Anthropic 文档系统，高级浅灰白背景，深灰文字，少量蓝绿色数据流线。大标题区域写“Claude Code 动态工作流”，副标题写“让 AI 为每个任务搭执行系统”。文字清晰、留白充足、适合手机端收藏。

## 02 核心定义

生成一张小红书 3:4 竖版信息图，标题“它不是一个 Prompt”。左侧是一张单独的 prompt 输入框，显得简单但承载过重；右侧是 workflow 控制台，包含“拆任务、调 agent、做验证、合并结果”四个模块，并连接多个子 agent。整体像产品说明书中的架构对比图。文字只保留短标签，模块大而清楚。

## 03 为什么需要

生成一张 3:4 竖版解释图，标题“复杂任务会压垮单个上下文”。左侧显示一个单 agent 同时承担计划、执行、验证、总结四个沉重模块，右侧显示多个 agent 分工协作，每个 agent 只负责一个小目标。画面采用干净 UI 插画和流程图混合风格，强调“单上下文过载”和“多 agent 分工”对比。

## 04 示例 Prompt 墙

生成一张 3:4 竖版 prompt 卡片墙，标题“哪些任务适合 workflow？”。画面有 6 张高级卡片，分别写：偶发测试失败、提炼规则、incident 根因、商业计划评审、80 份简历筛选、CLI 命名比赛。卡片像开发者知识库 UI，层级清晰，留白充足，中文短句清楚可读。

## 05 运行机制

生成一张 3:4 竖版架构图，标题“workflow 怎么跑起来？”。中心是一个 JavaScript workflow 文件图标，向外连接四个区域：subagents、模型选择、独立 worktree、结果汇总。画面像工程架构白板，但 UI 更精致，高级浅色背景，细线箭头，模块标签大字号。

## 06 三个失败模式

生成一张 3:4 竖版三栏对照信息图，标题“单 agent 常见 3 个问题”。三栏分别是“提前收工”“偏爱自己答案”“目标漂移”。每栏包含一个简洁图标、一个表现短句、一个 workflow 解法短句。整体像高端产品课程卡片，中文清晰，避免小字。

## 07 动态 vs 静态

生成一张 3:4 竖版对比图，标题“动态 workflow 强在哪？”。左侧是“静态 workflow：通用模板”，图形像固定工具箱；右侧是“动态 workflow：现场定制”，图形像根据任务自动生成的专用仪表盘。背景简洁，左右对比强，文字短而清楚。

## 08 Classify-and-act

生成一张 3:4 竖版流程图，标题“先分类，再行动”。顶部是输入任务池，中间是 classifier agent，下面分流到 bug、文档、研究、审查四个 agent 节点。用细线箭头连接，整体像智能路由系统 UI。

## 09 Fan-out-and-synthesize

生成一张 3:4 竖版并行任务图，标题“拆开并行，最后合并”。一个大任务在上方分裂成多条并行轨道，每条轨道都有一个 agent，底部汇入 synthesize 汇总模块，输出一份结构化报告。画面强调并行、等待屏障、合并。

## 10 Adversarial verification

生成一张 3:4 竖版验证流程图，标题“生成者和验证者分开”。左侧生成 agent 输出方案，中间是结果文档，右侧 verifier agent 按 rubric 检查，标出风险、遗漏、证据不足三个标签。整体像代码审查和事实核查 UI。

## 11 Generate-and-filter

生成一张 3:4 竖版漏斗信息图，标题“先多生成，再严格过滤”。顶部大量 idea 卡片进入漏斗，经过 rubric、verification、dedupe 三层过滤，底部只剩 top picks。风格高级、清晰、适合小红书知识卡。

## 12 Tournament

生成一张 3:4 竖版 tournament bracket 图，标题“让多个方案比赛”。多个 agent 方案 A/B/C/D/E/F 进入淘汰赛结构，judge agent 节点评判，最后选出 winner。像产品策略评选界面，中文标签清楚，结构不要拥挤。

## 13 Loop until done

生成一张 3:4 竖版循环流程图，标题“循环到真正完成”。流程为 run、inspect、fix、verify，形成闭环，旁边有 done condition 面板：无新错误、无新发现、验证通过。整体像自动化任务控制面板。

## 14 Use cases 地图

生成一张 3:4 竖版任务场景地图，标题“适合 workflow 的任务地图”。画面是 10 个模块组成的地图：重构迁移、深度研究、事实核查、排序筛选、规则遵守、根因调查、大规模 triage、探索品味、Evals、模型路由。每个模块一个小图标和短标签。

## 15 什么时候不要用

生成一张 3:4 竖版决策树，标题“不是每个任务都需要 workflow”。节点依次为：任务复杂吗？需要并行吗？需要验证吗？需要长期循环吗？如果都否，输出“直接用 Claude Code”；如果是，输出“考虑 workflow”。风格像清晰产品决策图。

## 16 提示技巧

生成一张 3:4 竖版提示词模板卡，标题“怎么让 Claude 用好 workflow？”。画面包含 4 张模板卡：明确模式、配合 /goal、配合 /loop、设置 token budget。每张卡只有一行中文示例，像高级 prompt cheat sheet。

## 17 保存和分享

生成一张 3:4 竖版文件流转图，标题“workflow 可以沉淀成资产”。流程为 workflow.js -> ~/.claude/workflows -> SKILL.md -> 团队复用。画面像文件系统和知识库结合的 UI，清楚展示保存、分发、复用。

## 18 总结

生成一张 3:4 竖版总结图，标题“从 AI 助手到任务指挥台”。左侧是单个 AI 助手图标，右侧是多 agent 控制台，中央箭头表示进化。底部短句：“复杂任务需要结构化协作”。高级科技教程收尾页，干净、有记忆点。
