Claude Code 新玩法：让 AI 自己组队干活

## 正文

很多人用 Claude Code，只把它当成一个会写代码的 AI 助手。

但动态工作流真正改变的是：
Claude Code 可以根据不同任务，临时搭一套“执行系统”。

这套系统不是一个 prompt，也不是简单多问几轮。

它可以拆任务、派子 agent、做交叉验证、合并结果，甚至决定哪些步骤需要更强模型，哪些步骤要放进独立工作区里跑。

比如：

一个测试 50 次才失败 1 次，可以让 workflow 反复复现问题，提出多个假设，在不同 worktree 里验证，直到找到有效原因。

你最近 50 次会话里反复纠正 Claude 的问题，也可以让 workflow 挖出来，整理成 CLAUDE.md 规则。

团队 Slack 里过去半年反复出现的 incident 根因，可以让 workflow 搜索、聚类、去重，再找出没人提 ticket 的问题。

80 份简历、商业计划评审、代码库模型重命名、技术博客事实核查，这些都不是单次问答，更适合一套工作流。

为什么？

因为复杂任务里，单个 agent 很容易遇到三个问题：

第一，做到一半就以为做完了。
比如安全审查有 50 项，它处理 20 项就开始总结。

第二，偏爱自己的答案。
让同一个 agent 既生成方案又审查方案，很容易变成自己给自己打高分。

第三，目标漂移。
长任务经过多轮上下文压缩后，边界条件、反例和“不要做什么”很容易丢失。

动态 workflow 的解决方式是：
把任务拆给多个有独立上下文的 Claude，每个子 agent 只负责一个清晰目标，再由 workflow 负责调度、等待、验证和合并。

它常见有几种模式：

Classify-and-act：
先分类，再分发。适合 support tickets、bug 列表、文档问题、风险等级判断。

Fan-out-and-synthesize：
把任务拆成很多小块并行处理，最后汇总。适合大规模重构、批量研究、模块审查。

Adversarial verification：
生成 agent 做结果，验证 agent 专门挑错。适合事实核查、代码审查、安全审查。

Generate-and-filter：
先生成大量想法，再按标准过滤。适合命名、标题、设计方案、prompt 方案。

Tournament：
多个 agent 用不同方案竞争，再两两比较选优。适合品味判断强的任务。

Loop until done：
不预设固定轮数，而是循环到没有新错误、没有新发现、验证通过为止。适合调试、triage、长期监控。

它能用在哪些地方？

大型迁移和重构：拆调用点、测试、模块，多个 worktree 并行修，再互相 review。

深度研究：fan-out 搜索，抓来源，验证 claims，综合成报告。

深度验证：先抽取报告里的事实断言，再逐条核查来源质量。

排序：不要一次性塞 1000 行让 AI 打分，而是用成对比较或 tournament 排序。

规则遵守：每条规则派一个 verifier agent，专门检查有没有漏。

根因分析：日志、文件、数据分别生成假设，再让 verifier 和 refuter 交叉检查。

大规模 triage：分类、去重、尝试修复或升级给人工。

探索和品味判断：让多个方案竞争，再按 rubric 选择。

Evals：多个 agent 在独立 worktree 里跑任务，再用 comparison agent 评分。

模型路由：先判断任务复杂度，再决定用 Sonnet 还是 Opus。

但 workflow 不是所有任务都要用。

它会消耗更多 token，也会让执行结构更复杂。

一个明确 bug、一个小功能、一个局部解释，直接让 Claude Code 做通常就够了。

真正适合 workflow 的，是那些容易遗漏、需要并行、需要验证、需要长期循环、需要多角度判断的任务。

使用时可以这样提示：

“用 workflow 处理这个任务。”

“用 fan-out-and-synthesize，把每个模块分开分析，最后综合。”

“为每个结果创建一个验证 agent，按 rubric 反向检查。”

“用 tournament 生成多个方案并选出前三名。”

“配合 /goal，不要在满足完成条件前停止。”

“配合 /loop，让它持续处理新的 triage 项。”

“使用 10k token 预算，在预算内完成。”

workflow 还可以保存和分享。

保存后可以放进 `~/.claude/workflows`，也可以放进 skill 里作为模板复用。

我觉得动态 workflow 最重要的变化是：

AI 不只是回答问题，而是开始为任务组织一套工作系统。

单个 agent 像一个助手。

workflow 像一个任务指挥台。

当任务足够复杂时，真正提升质量的不是“多问 AI 几次”，而是让它按结构拆解、并行执行、互相验证、直到完成。

你现在用 Claude Code，最想把哪类任务改成 workflow？
