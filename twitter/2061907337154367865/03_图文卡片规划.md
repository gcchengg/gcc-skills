# 图文卡片规划

整体风格：高级科技产品教程 UI。3:4 小红书竖版。浅灰白背景，细线框、流程箭头、代码块、prompt 卡片、控制台面板、模块卡片。强调色使用 Anthropic 风格暖白、深灰、克制蓝绿。不要花哨贴纸，不要密集小字，不要赛博朋克。

## 01 封面

标题：Claude Code 动态工作流  
副标题：让 AI 为每个任务临时搭一套执行系统  
画面：一个中央 workflow 控制台，向外连接多个子 agent 节点：研究、编码、验证、总结、排序。

## 02 核心定义

标题：它不是一个 Prompt  
正文点：
- 动态 workflow 是任务执行系统
- 先写 harness，再执行任务
- 拆分、调度、验证、合并
画面：左侧“单个 prompt”，右侧“workflow 控制台 + 多 agent 网络”。

## 03 为什么需要

标题：复杂任务会压垮单个上下文  
正文点：
- 规划和执行挤在一起
- 长任务会丢细节
- 并行和验证能力不足
画面：一个单 agent 背着 plan、execute、verify、summarize 四个模块，对比多个 agent 分工。

## 04 示例 Prompt 墙

标题：哪些任务适合 workflow？  
正文点：
- 复现偶发测试失败
- 提炼 CLAUDE.md 规则
- 分析 incident 根因
- 评审商业计划
- 筛选 80 份简历
- CLI 命名 tournament
画面：6 张 prompt 卡片墙，每张卡一个场景。

## 05 运行机制

标题：workflow 怎么跑起来？  
正文点：
- 执行一个 JavaScript 文件
- 创建和协调 subagents
- 使用 JSON / Array 处理结果
- 决定模型和 worktree
画面：JS workflow 文件作为中控，连接模型选择器、worktree、子 agent、结果汇总器。

## 06 三个失败模式

标题：单 agent 常见 3 个问题  
正文点：
- 做一半就宣布完成
- 偏爱自己的答案
- 长任务目标漂移
画面：三栏对照表，每栏一个失败模式、表现和 workflow 对应解法。

## 07 动态 vs 静态

标题：动态 workflow 强在哪？  
正文点：
- 静态 workflow：提前写好，偏通用
- 动态 workflow：为当前任务现场定制
- 任务不同，执行系统也不同
画面：左侧通用瑞士军刀，右侧为具体任务生成的专用仪表盘。

## 08 模式一：Classify-and-act

标题：先分类，再行动  
正文点：
- classifier agent 判断任务类型
- 路由给不同 agent
- 也可用于最终输出分类
画面：一个分类器节点分流到 bug、文档、研究、审查四个 agent。

## 09 模式二：Fan-out-and-synthesize

标题：拆开并行，最后合并  
正文点：
- 大任务拆成多个小任务
- 每个 agent 有干净上下文
- synthesize 等待并合并结果
画面：一个任务分裂成多条并行轨道，最后汇入一份报告。

## 10 模式三：Adversarial verification

标题：生成者和验证者分开  
正文点：
- 生成 agent 负责产出
- verifier agent 专门挑错
- 减少自己审自己
画面：左侧 output，右侧 verifier 用 rubric 检查，标出风险项。

## 11 模式四：Generate-and-filter

标题：先多生成，再严格过滤  
正文点：
- 批量生成想法
- 按标准筛选
- 去重，只留高质量结果
画面：漏斗图：ideas -> rubric -> verification -> top picks。

## 12 模式五：Tournament

标题：让多个方案比赛  
正文点：
- 多个 agent 同题竞争
- judge agent 两两比较
- 最后选出赢家
画面：淘汰赛 bracket，方案 A/B/C/D 逐轮晋级。

## 13 模式六：Loop until done

标题：不要固定轮数，循环到完成  
正文点：
- 没有新发现才停止
- 没有错误日志才停止
- 验证通过才停止
画面：循环箭头围绕“run -> inspect -> fix -> verify”，终点是 done condition。

## 14 Use cases 地图

标题：适合 workflow 的任务地图  
正文点：
- 重构迁移
- 深度研究
- 事实核查
- 排序筛选
- 根因调查
- 大规模 triage
- evals 和模型路由
画面：一张地图式看板，10 个任务场景模块。

## 15 什么时候不要用

标题：不是每个任务都需要 workflow  
正文点：
- 会消耗更多 token
- 简单 bug 不必上复杂系统
- 复杂、并行、验证型任务才值得
画面：决策树：任务是否复杂？是否需要并行？是否需要验证？是否长期循环？

## 16 提示技巧

标题：怎么让 Claude 用好 workflow？  
正文点：
- 明确模式
- 配合 /goal
- 配合 /loop
- 设置 token budget
画面：4 张提示词模板卡。

## 17 保存和分享

标题：workflow 可以沉淀成资产  
正文点：
- 保存到 workflows
- 放进 skill
- 作为模板复用
画面：workflow.js -> ~/.claude/workflows -> SKILL.md -> 团队复用。

## 18 总结

标题：从 AI 助手到任务指挥台  
正文点：
- 单 agent 是助手
- workflow 是执行系统
- 复杂任务需要结构化协作
画面：从单个 assistant 图标进化到多 agent 控制台。
