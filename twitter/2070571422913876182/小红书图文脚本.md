# 小红书图文脚本

## 01 封面

标题：AI Agent 的下一站

副标题：不是聊天框，是组织成员

画面：一个企业协作系统中，AI 节点连接 Slack/代码库/知识库/监控/任务系统，整体像组织工作网络。

重点：竖版 4:5，标题大，移动端缩略图可读。

## 02 先别把它理解成聊天机器人

标题：不是“多一个机器人”

正文：真正的变化是：AI 开始拥有组织身份、工具权限、共享上下文和安全边界。

画面：左侧“聊天框”，右侧“组织级工作系统”，形成对比。

## 03 什么是 Agent Harness？

标题：Agent Harness 是什么？

正文：它是让 Agent 真正工作的运行环境：身份、工具、上下文、权限、安全、记忆、汇报机制。

画面：中间一个 Agent 核心，周围环绕 7 个模块。

## 04 变化一：从个人到团队

标题：从 single-player 到 multi-player

正文：个人助手只能帮一个人；组织级 Agent 可以进入事故排查、长讨论整理、复盘和行动项追踪。

画面：一个人对话 vs 多人协作线程。

## 05 变化二：从同步到异步

标题：从聊天到委托

正文：长任务不适合一直问答。你给 Agent 目标，它后台执行、检查结果、失败后纠偏。

画面：目标、执行、验证、反馈的循环图。

## 06 异步 Agent 为什么现在才成立？

标题：异步 Agent 需要安全底座

正文：长任务能力、prompt injection 防护、action 审查、安全权限模型、goal primitive，缺一不可。

画面：五层安全/能力堆栈。

## 07 变化三：从被动到主动

标题：Agent 不能只等你问

正文：实验卡住、指标异常、频道出现关键信息时，它应该主动提醒，而不是安静失败。

画面：条件触发器连接到提醒气泡。

## 08 三个真实使用场景

标题：组织级 Agent 最适合这 3 类事

正文：实验监控、主动搜索历史经验、频道 watcher。

画面：三栏卡片，每栏一个场景。

## 09 对 Codex 的启发

标题：Codex 也会走向组织级

正文：真正重要的不只是写代码，而是共享 skill、connector、workflow、review gate 和 dashboard。

画面：Codex 连接代码库、PR、CI、文档、任务系统。

## 10 总结

标题：AI Agent 的分水岭

正文：从个人外挂，到组织基础设施。未来的 Agent 不只回答问题，还会参与协作、长期执行、主动提醒。

画面：一条从“个人助手”到“组织工作系统”的演化路径。
