# WorkBuddy 从 0 到 1：普通人也能用的 AI 助手完整指南

汇报要写，数据要理，PPT 要出，代码要改。很多人不是不知道 AI 有用，而是卡在注册、支付、安装、网络和复杂配置上。

WorkBuddy 试图补上这块缺口：用微信登录，把模型、Skills、连接器、知识库、自动化和远程控制放进一个桌面端。对于不准备折腾开发环境、主要想处理日常办公的人，它更像一位能真正接活的数字同事。

这篇文章从安装、界面、模式、模型、专家、Skills、连接器一路讲到办公与开发实战，并补上最容易被忽略的权限、积分和远程控制风险。

## 一、先装上：门槛被压缩到微信扫码

WorkBuddy 提供 macOS 和 Windows 客户端。选择对应系统下载安装，打开后可以直接微信扫码登录。相比 API Key、双重验证和代理配置，这种入口对普通用户友好得多。

但“登录简单”不等于“使用没有成本”。进入主界面后，先花两分钟理解模式、权限和工作空间，能避免后面白白消耗积分或把文件放乱。

## 二、主界面：三个场景，一套工作台

对话区上方有三类场景：代码开发、日常办公、设计创意。切换场景后，快捷入口会同步变化。

- 日常办公：文档处理、数据分析与可视化、深度研究、幻灯片。
- 代码开发：日常开发、网站开发、Agent 应用、Skill 开发。
- 设计创意：网站、App、PPT、原型和品牌设计。

快捷入口不是简单的分类标签。继续进入“日常办公—文档处理”，会看到预置提示词模板。新手只需要替换字段，就能把含糊需求变成结构化任务。

### 三种工作模式一定要分清

- **Craft**：完整 Agent 模式，收到需求便开始执行。
- **Ask**：普通问答，只聊天，不直接跑任务。
- **Plan**：先输出计划，确认后再执行。

WorkBuddy 默认是 Craft。只是想问一句话却没有切换模式，任务可能立刻启动并消耗积分。还没有想清楚时先用 Plan；只需要知识问答时用 Ask；需求和材料都明确后再用 Craft。

### 模型怎么选

平台提供腾讯混元、DeepSeek、GLM、Kimi 等国产模型，不同模型的积分消耗不同。没有偏好时，可以先选价格和综合能力比较均衡的模型，再根据任务结果调整。模型名单、版本和计费会变化，实际选择以客户端当时展示为准。

也可以在“设置—模型—添加模型”中接入兼容 OpenAI 协议的接口。这样可以继续使用自己已有的模型服务，但 API Key 属于敏感凭证，应只在可信客户端内配置，并定期检查权限与费用。

### 权限：默认权限比完全访问更适合新手

默认权限会在潜在风险动作前停下来确认；完全访问则允许任务连续执行。为了省弹窗而直接开放完全访问，看起来顺手，实际会放大误删文件、错误上传或执行意外命令的风险。

更稳妥的做法是：日常保持默认权限；只在任务范围清晰、目录已备份、执行步骤可验证时，短时间扩大权限；完成后再恢复。

### 上传入口与工作空间

对话框右侧的加号可以添加本地文件、腾讯文档和知识库，并可联动 ima 知识库。

工作空间可以理解成项目文件夹。任务开始前选好目录，Agent 会围绕这里读写文件；任务结束后，任务记录、空间目录和本地文件夹会形成对应关系。越早按项目分类，后面越容易找到产物。

## 三、专家、专家团、Skills 与连接器

### 专家：预先配置好的垂直 Agent

专家已经预设角色、工具和知识方向。内容创作专家、UI 设计师、AI 图像提示词工程师等，都可以像普通对话一样使用，但回答会带有更明确的专业视角。

### 专家团：多个 Agent 分工协作

专家团会由负责人拆任务，再分给产品经理、架构师、工程师、QA 等角色并行推进。它适合跨专业、交付链较长的任务，但多 Agent 通信会显著增加积分消耗，可能达到单专家的数倍。简单任务不要为了“阵容豪华”而上专家团。

有稳定方法论时，也可以创建自己的专家，把重复使用的流程、标准和知识固化下来。

### Skills：可复用的做事方法

Skills 市场包含官方推荐、社区聚合 Skillub 和成套套件。它解决的不是“再加一个聊天机器人”，而是让 Agent 学会某种可复用流程，例如整理文档、生成演示文稿、开发前端页面或管理服务器。

安装 Skill 前应检查来源、权限、说明和实际动作范围。社区技能能提高效率，也可能包含质量不稳定或权限过宽的问题。

### 连接器：把外部服务接入 Agent

连接器即 MCP，可让 WorkBuddy 操作外部服务。腾讯生态是它的明显优势：QQ 邮箱、腾讯会议、腾讯文档等可通过扫码授权接入，也提供其他服务和自定义连接器入口。

连接器一旦获得授权，就可能读取、搜索、整理甚至发送内容。建议坚持最小权限原则，不用的连接器及时撤销；涉及邮件发送、文件外传和对外发布时，保留人工确认。

## 四、开工前，把这些设置调好

### 技能自动更新

希望 Skills 持续获取改进可以开启自动更新；对权限敏感的生产环境，则应先查看变更再更新。

### 锁屏远程

开启后，电脑锁屏时任务仍可运行。它适合长任务，却会改变设备的休眠与持续运行状态。笔记本外出、共享电脑或包含敏感资料的环境，开启前要评估电源、网络和隐私风险。

### 对话记忆

记忆功能会从聊天中提炼偏好和背景，用久后更懂你的语气与习惯。便利的另一面是信息会持续沉淀。不要把密码、身份证号、财务明细、客户机密等内容当成普通记忆素材；定期查看和清理记忆更稳妥。

### 自定义指令

自定义指令相当于整个系统的工作总纲。推荐写清五件事：先理解再执行、简洁优先、精准修改、目标可验证、完成后验证。真正有效的指令不是越长越好，而是能持续约束行为。

## 五、办公实战：从一句白话到可检查的产物

一个典型流程是：

1. 切换到“日常办公”。
2. 选择工作空间，或临时上传材料。
3. 选择合适模型。
4. 输入需求，并使用“优化提示词”补全结构。
5. 检查任务目标、输入范围、输出格式和截止条件。
6. 用 Plan 先看计划，确认后再执行。
7. 根据右侧 Todo 跟踪进度，最后检查预览和本地文件。

比如整理一批 Skills 相关文章，不要只说“帮我整理一下”。更好的要求是：说明材料所在目录、要提取的字段、希望按什么维度分类、最终交付 Markdown 还是 PPT，以及哪些信息不能遗漏。

文档、数据分析、PPT 和图表都能接，但质量同时取决于模型、提示词、输入材料和验收标准。Agent 能完成交付，不代表交付天然正确。

## 六、开发实战：小项目能做，复杂工程仍需谨慎

开发一个世界杯主题网页，可以这样走：

1. 切换到“代码开发”，选择“网站开发”。
2. 描述页面目标、风格、模块和交互。
3. 使用 Plan 模式先看方案。
4. 回答它对技术栈、页面结构、素材和部署方式的追问。
5. 确认后执行，第一版出来后再用前端 Skill 优化。
6. 如果配置了服务器管理 Skill，可以继续完成部署，但上线前必须检查域名、密钥、费用和公开范围。

目前国产模型做小网页、小工具和轻量项目已经可用，但复杂工程对架构理解、长期上下文、调试和代码质量的要求更高。复杂项目仍应使用成熟的编码 Agent，并保留代码审查、测试、版本控制和人工验收。

## 七、微信远程控制：方便，也要设置边界

WorkBuddy 的助理功能可以与微信小程序连接。客户端打开助理设置并扫码授权后，手机端通常有两种方式：

- **云端工作**：任务在云端沙箱运行，电脑关机也可以执行。
- **连接电脑**：远程调用本地电脑，适合读取本地文件的任务。

一个常见场景是人在外面，临时需要把电脑里的文件发给财务。配置 QQ 邮箱连接器后，可以远程查找并发送；没有连接器，也可以先把文件返回到小程序再手动转发。

这也是风险最高的一段链路：手机指令、云端服务、本地文件和邮件发送被串在一起。建议把远程可访问目录限制在专门工作区，不要开放整个硬盘；发送邮件和外传文件保留最终确认；遗失手机后立即撤销授权。

## 八、普通人真正需要的，不是更会聊天的 AI

Agent 的最大价值，不只是写出漂亮代码，而是把每天琐碎、重复、让人烦躁的工作变成可交付流程：整理数据、制作 PPT、生成文档、开发小工具、查找文件。

WorkBuddy 的优势，是把国内用户熟悉的微信登录、腾讯生态、模型、Skills 和远程控制连在一起，降低了开始使用的门槛。它的限制也很明确：积分会消耗，模型能力有边界，连接器和完全权限会带来风险，复杂工程不能只靠“一句话”。

真正好用的方法不是把所有权限都交出去，而是建立一条清晰的协作链：先说清目标，再让 Agent 规划；限定工作空间和权限；执行中看 Todo；交付后检查事实、文件和费用。做到这些，AI 才不是一个偶尔打开的聊天框，而是一位可管理、可验收的数字同事。
